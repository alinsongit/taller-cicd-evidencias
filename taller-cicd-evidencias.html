5. Evidencia del Paso 1 — Pipeline en GitHub Actions (.github/workflows/ci.yml)

name: CI Pipeline Spring Boot

on:
  push:
    branches: [ main, develop ]
  pull_request:
    branches: [ main ]

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout del codigo
        uses: actions/checkout@v4
      - name: Configurar JDK 21
        uses: actions/setup-java@v4
        with:
          java-version: '21'
          distribution: 'temurin'
          cache: maven
      - name: Build con Maven
        run: mvn -B clean compile
        working-directory: maddelivery
      - name: Ejecutar pruebas unitarias
        run: mvn -B test
        working-directory: maddelivery
      - name: Reporte de cobertura JaCoCo
        run: mvn -B jacoco:report
        working-directory: maddelivery
      - name: Publicar reporte como artefacto
        uses: actions/upload-artifact@v4
        with:
          name: reporte-jacoco
          path: maddelivery/target/site/jacoco
      - name: Verificar variable de entorno
        env:
          APP_ENV: ${{ secrets.APP_ENV_DEMO }}
        run: echo "Ejecutando en el ambiente configurado"

6. Evidencia del Paso 5 — Configuración de secretos

En GitHub (Settings → Secrets and variables → Actions) se define el secreto APP_ENV_DEMO (valor de ejemplo: workshop-2026). El pipeline lo consume con ${{ secrets.APP_ENV_DEMO }} y lo expone como variable de entorno APP_ENV en la etapa final. Los secretos nunca se registran en el log de la acción.
